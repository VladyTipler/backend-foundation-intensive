# Готовый frontend для backend-интенсива

React + TypeScript + Vite. Писать или изучать frontend для прохождения практики не нужно.
Здесь **нет mock/demo-режима**, реализации backend, таблиц или миграций. Интерфейс вызывает только твой API.

## Запуск из корня репозитория

```bash
npm run web:install
npm run web:dev
```

Открой `http://127.0.0.1:5173`. Backend запускается отдельно (`npm run dev`, порт 3000); контейнеры — `docker compose up -d --wait`.
Нормальная последовательность: контейнеры → backend в терминале 1 → frontend в терминале 2. Оба терминала остаются открытыми. Остановка каждого — Ctrl+C.

Для чистой установки весь путь есть в корневом README. Node.js 24 — единая версия курса. У `web/` свой `package-lock.json`; корневой `npm ci` не ставит его зависимости, поэтому нужен `web:install`.

## Как проходить уроки

По умолчанию включён День 0: клиент делает только `GET /health`. Пустая БД здесь нормальна.
Выбирай день в меню слева. День 2 открывает вакансии; День 3 — аккаунт и отклики; День 4 — экспорт. После этого работают все разделы.
Это переключатель интерфейса, а не проверка реализации и не механизм безопасности. Backend всегда сам проверяет права.
Перед подготовкой создай требуемую структуру из задания. Открой lab.cmd / lab.command или npm run lab и выбери день. Новый помощник добавляет учебные данные без очистки; db:clean/reset остаются отдельными разрушительными командами. Подробнее: [подготовка каждого дня](../docs/lab-preparation.md).
`GET /jobs` ещё нет в starter, поэтому 404 после перехода к Дню 2 — ожидаемый результат до твоей реализации.

## Договор с backend

Полный [API-контракт](../docs/api-contract.md) описывает методы, JSON, ошибки, сессию, CSRF, фильтрацию, пагинацию и экспорт.
Имена объектов API не диктуют схему БД: нормализованные таблицы можно собирать в нужный ответ через SQL/ORM.

## Адрес API и упражнение по CORS

По умолчанию запрос браузера `/api/jobs` идёт в Vite и передаётся в Node как `/jobs`. Это [dev proxy Vite](https://vite.dev/config/server-options#server-proxy), не обход проверки прав. Он позволяет не отвлекаться на CORS до Дня 3.
Если backend слушает другой порт, создай `web/.env.local` с `API_PROXY_TARGET=http://127.0.0.1:НОВЫЙ_ПОРТ` и перезапусти frontend. Корневой `.env` и `web/.env.local` — разные файлы.
Для отдельной практики CORS укажи `VITE_API_BASE=http://127.0.0.1:3000` в `web/.env.local`. Тогда браузер обращается к API напрямую. Сервер должен разрешать конкретный origin фронтенда, credentials и заголовки `Content-Type`, `X-CSRF-Token`, `Idempotency-Key`, обрабатывать OPTIONS; для инспектора открыть `X-Request-Id` через Expose-Headers. Не ставь wildcard вместе с credentials.
Не смешивай localhost и 127.0.0.1 при отладке cookie; открывай UI по одному адресу. Разрешённый Origin проверяется на backend, включая порт frontend 5173.
[Переменные VITE_* доступны браузеру](https://vite.dev/guide/env-and-mode). Секретов в них быть не должно.

## Проверка самого frontend

Из `web/`: `npx playwright install chromium` — однократная установка тестового браузера. Из корня: `npm run web:test` — браузерные тесты.
Тесты используют перехват запросов Playwright и подставной API **только в tests/**. Они проверяют клиент, а не PostgreSQL, BullMQ или безопасность backend ученика. Эти фикстуры не импортируются в src и не попадают в сборку.
`npm run web:build` создаёт `web/dist`; `npm run web:preview` позволяет локально посмотреть сборку. Для настоящего деплоя обслуживай web/dist статическим сервером с маршрутом `/api/*` к backend: dev proxy не появляется в production автоматически.
Журнал запросов не отправляется ни в какую аналитику, хранится в памяти вкладки и очищается при перезагрузке. Он ограничивает объём показанных данных; для полного ответа есть Network в DevTools. Браузерные инструменты видят реальные запросы — не используй рабочие пароли для учебной демонстрации.

## Что frontend не проверяет вместо тебя

Он не доказывает наличие индекса, отсутствие N+1, устойчивость очереди или защиту от чужого userId. Такие упражнения выполняй через SQL, логи, остановку worker и прямые HTTP-запросы. На обычном экране нет автоматического теста безопасности.
