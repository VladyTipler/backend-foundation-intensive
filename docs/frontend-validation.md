# Проверка готового клиента

Дата: 19 сентября 2026. Среда: Windows, Node.js 24.13.1, Chromium через Playwright.

## Выполнено

- TypeScript frontend: без ошибок.
- Production build Vite: успешная сборка `web/dist`.
- 13 браузерных тестов Playwright: **13 passed**.
- Визуально просмотрены экран обзора, список вакансий и мобильный экран шириной 390 px.

## Что покрывают 13 тестов

День 0 обращается только к `/health`; будущие разделы отключены. Сетевая ошибка показана явно.
Для вакансий проверены 404, неправильный JSON с HTTP 200, пустой список, серверные поиск и пагинация, создание, изменение и удаление. Отказ записи не превращается в видимый успех.
Для аккаунта проверены login, получение/отправка CSRF-токена, скрытие пароля и токенов в инспекторе, восстановление сессии после перезагрузки и logout.
Для откликов — создание без userId клиента, ответ 409 на дубликат и смена статуса.
Для экспорта — сохранение Idempotency-Key после 504, повторное создание с тем же ключом, опрос статуса до завершения и скачивание CSV-ответа.
Также проверены возврат к Дню 0 и отсутствие горизонтального скролла на мобильной ширине.

## Граница проверки

**Тесты используют подставной API в `web/tests/fixture.ts` через перехват Playwright.** Он нужен для проверки самого готового клиента и не подключается при обычном запуске приложения. В `web/src` нет демонстрационных данных.
Этот прогон НЕ доказывает корректность backend ученика, запросов PostgreSQL, миграций, сессионного хранилища, авторизации или BullMQ. Реальный starter по-прежнему реализует только `/health`. Остальные endpoint и проверки безопасности остаются заданиями курса.
Тест не делает вывод «защита CSRF работает на сервере»: он проверяет, что клиент запрашивает токен и отправляет нужный заголовок.

## Повторить

Из корня: `npm run web:install`. Один раз из `web/`: `npx playwright install chromium`.
Затем из корня: `npm run web:typecheck`, `npm run web:build`, `npm run web:test`.
